# 💡 UniTest — Идеи, улучшения и проблемы

---

## 🔴 БАГИ И ПРОБЛЕМЫ (нужно исправить)

### 1. Медиафайлы хранятся в base64 внутри MongoDB
**Файл:** `server/routes/tests.js` (строки 24–46)

Когда учитель загружает картинку/видео/аудио к вопросу, файл конвертируется в base64 data URL и сохраняется прямо в документе теста в MongoDB. Это:
- Раздувает размер документа (одна картинка 5МБ = 7МБ base64 строка)
- Упирается в лимит MongoDB документа (16 МБ)
- Замедляет загрузку теста (браузер скачивает весь base64 в JSON)

**Решение:** загружать файлы в S3/DigitalOcean Spaces/Cloudinary и хранить только URL.

---

### 2. JWT без refresh-token — юзера разлогинивает каждые 7 дней
**Файл:** `server/routes/auth.js` (строка 34, 77)

Токен выдаётся на 7 дней без возможности обновления. Когда он истекает — юзер разлогинивается без предупреждения.

**Решение:** добавить refresh-token (httpOnly cookie, rotated при каждом обновлении).

---

### 3. Нет верификации email при регистрации
**Файл:** `server/routes/auth.js` (строки 21–53)

Любой может зарегистрировать аккаунт с чужим email. Нет подтверждения через письмо.

**Решение:** отправлять письмо с кодом/ссылкой подтверждения. Не давать доступ к платформе до верификации.

---

### 4. Нет "Забыл пароль"
**Файл:** `server/routes/auth.js`

Если пользователь забыл пароль — единственный вариант: обратиться к админу. Нет самостоятельного сброса пароля.

**Решение:** добавить `/api/auth/forgot-password` и `/api/auth/reset-password` с отправкой письма.

---

### 5. `GET /results/my` скачивает ВСЕ результаты без пагинации
**Файл:** `server/routes/results.js` (строки 222–232)

Если студент прошёл 500 тестов — фронтенд скачивает все 500 результатов одним запросом. Страница "Мои результаты" начнёт тормозить.

**Решение:** добавить `?page=1&limit=20` пагинацию.

---

### 6. CORS открыт для ВСЕХ источников
**Файл:** `server/index.js` (строка 24)

`app.use(cors())` — принимает запросы с любого домена. В продакшене нужно ограничить до вашего домена.

**Решение:** `cors({ origin: ['https://unitest.page'], credentials: true })`.

---

### 7. Отсутствует валидация входных данных на бэкенде
**Файл:** `server/routes/tests.js` (строка 10–22)

При создании теста бэкенд принимает `...req.body` без валидации. Злоумышленник может отправить любые поля (включая `creator`, `rating`, `attemptCount`).

**Решение:** использовать библиотеку `joi` или `zod` для валидации тела запроса; белый список допустимых полей.

---

### 8. Дублирующиеся ключи в LanguageContext.jsx
**Файл:** `client/src/context/LanguageContext.jsx` (строки 266, 327, 601, 662, 936, 997)

Vite выдаёт предупреждения: `Duplicate key "exportJSON"` и `Duplicate key "navigation"` во всех трёх языках. Второе значение перезаписывает первое.

**Решение:** удалить дубликаты, оставив одну версию каждого ключа.

---

### 9. `index.html` кешируется при старте сервера
**Файл:** `server/index.js` (строки 57–62)

Сервер читает `index.html` один раз при старте (`readFileSync`). Если пересобрать фронтенд без рестарта сервера — пользователи получают старый HTML с невалидными хешами JS-файлов (белый экран).

**Решение:** читать `index.html` при каждом запросе, или использовать `res.sendFile()` с no-cache заголовками.

---

### 10. Эссе-ответы не имеют уведомления для учителя
**Файл:** `server/routes/results.js` (строки 122–127)

Когда студент отвечает эссе — оно получает 0 баллов и ждёт ручной проверки. Но учитель никак не узнаёт, что есть непроверенные эссе (кроме как вручную зайти в результаты каждого теста).

**Решение:** push-нотификация + бейдж "N эссе ждут проверки" на дэшборде.

---

### 11. Нет лимита на количество участников в группе
**Файл:** `server/routes/groups.js` (строки 68–88)

Любой может присоединиться к группе по коду. Нет максимального количества участников и нет одобрения от админа.

---

### 12. Guest attempt tracking можно обойти
**Файл:** `server/routes/results.js` (строки 19–32)

Ограничение попыток для гостей основано на `guestId` (browser fingerprint) или `guestName`. Гость может просто очистить localStorage или ввести другое имя — и проходить тест бесконечно.

## 🟡 ПОЛЕЗНЫЕ УЛУЧШЕНИЯ

### 13. Экспорт результатов в Excel/PDF
**Что:** Учитель нажимает кнопку "Скачать результаты" → получает `.xlsx` файл с таблицей: ФИО, балл, процент, время, нарушения.

**Зачем:** Преподаватели в универах должны сдавать ведомости. Сейчас им надо вручную переписывать результаты.

**Как:** библиотека `exceljs` на бэке, эндпоинт `GET /api/results/test/:testId/export`.

---

### 14. Дэшборд учителя — виджет "Ждут проверки"
**Что:** На дэшборде карточка: "5 эссе ждут проверки" с прямой ссылкой на каждый тест.

**Зачем:** Учитель не должен перебирать тесты вручную. Сейчас это основной UX pain point.

---

### 15. Дедлайн для группового теста с обратным отсчётом
**Что:** В модели Group есть `deadline` для назначенных тестов, но на фронтенде нет обратного отсчёта и предупреждений.

**Как:** показать таймер "до дедлайна: 2ч 30м" на карточке теста. За 1 час — push-уведомление.

---

### 16. Статистика по вопросам для учителя (уже есть API, нет UI)
**Что:** Эндпоинт `GET /api/results/analytics/:testId` уже работает — показывает процент правильных ответов на каждый вопрос. Но на фронтенде этих данных нет.

**Как:** добавить вкладку "Аналитика вопросов" на странице результатов теста. Гистограмма: какие вопросы самые сложные, какие варианты ответа выбирают чаще.

---

### 17. Дублирование теста — нет кнопки на фронтенде
**Что:** API `POST /api/tests/:id/duplicate` уже работает, но на UI нет кнопки "Дублировать тест".

**Как:** добавить кнопку ⧉ на карточке теста в "Мои тесты" → вызов API → toast "Тест дублирован".

---

### 18. Добавить `helmet` для HTTP security headers
**Что:** Заголовки безопасности (CSP, X-Frame-Options, HSTS) не настроены.

**Как:** `npm install helmet` → `app.use(helmet())`. Одна строка кода — серьёзно повышает безопасность.

## 🟢 КРУТЫЕ ФИЧИ (новый функционал)

### 19. 🤖 AI-автопроверка эссе
**Что:** Вместо ручной проверки учителем — GPT оценивает эссе по критериям (содержание, грамотность, полнота ответа) и ставит балл + комментарий. Учитель может одобрить или изменить оценку.

**Зачем:** Экономит часы ручной работы. Особенно полезно при 100+ студентах.

---

### 20. 📊 Аналитика прогресса студента
**Что:** Страница "Мой прогресс" — графики: как менялся средний балл за неделю/месяц, какие темы (теги) сильные/слабые, тренд по предметам.

**Зачем:** Студент видит свой рост, а не просто список пройденных тестов.

---

### 21. 📱 PWA (Progressive Web App) + Push уведомления
**Что:** Добавить `manifest.json` + service worker → приложение можно "установить" на телефон с домашнего экрана. Push-уведомления: "Вам назначен новый тест", "Дедлайн через 2 часа".

**Зачем:** Студенты живут в телефоне. PWA даёт native-like опыт без App Store.

---

### 22. 🔗 Интеграция с LMS (Google Classroom / Moodle)
**Что:** Синхронизация групп и оценок с Google Classroom. Учитель привязывает группу UniTest → оценки автоматически попадают в журнал Google Classroom.

**Зачем:** Универы и школы уже используют Google Classroom. Интеграция = серьёзный плюс для adoption.

---

### 23. 🎮 Режим "Квиз-баттл" (PvP в реальном времени)
**Что:** Два (или больше) студента проходят тест одновременно с live-таблицей лидеров. Кто быстрее и точнее — тот выше. Анимации правильных/неправильных ответов оппонента.

**Зачем:** Геймификация. Студенты будут сами хотеть пройти тест ради соревнования. Использовать WebSocket (Socket.io).

---

### 24. 🏆 Система достижений
**Что:** Бейджи: "Первый тест", "10 тестов подряд", "100% три раза", "Без нарушений", "Все эссе проверены" (для учителя). Отображается в профиле.

**Зачем:** Геймификация для мотивации. Студентам нравится собирать достижения.

---

### 25. 📋 Шаблоны тестов
**Что:** Готовые шаблоны: "Экзамен (30 вопросов, таймер 60 мин, анти-чит)", "Быстрый опрос (5 вопросов, без лимита, публичный)", "Домашнее задание (без таймера, 3 попытки)". Учитель выбирает шаблон → настройки заполняются автоматически.

**Зачем:** Сейчас каждый тест настраивается с нуля. Шаблоны экономят 2–3 минуты.

---

### 26. 🔍 Поиск и каталог публичных тестов
**Что:** Полноценная страница "Библиотека тестов" с фильтрами: предмет, рейтинг, количество вопросов, автор. Карточки тестов с превью.

**Зачем:** Учителя могут использовать тесты друг друга вместо создания с нуля. Контент растёт органически.

---

### 27. 📝 Банк вопросов — импорт из Quizlet/Anki
**Что:** Импортировать карточки из Quizlet (через скопированный текст или API) → автоматически конвертировать в вопросы single-choice/fill-blank.

**Зачем:** У многих учителей уже есть материалы на Quizlet. Импорт = быстрый переход на UniTest.

---

### 28. 🌐 WebSocket для live-уведомлений
**Что:** Сейчас уведомления приходят только при обновлении страницы (polling). С WebSocket — нотификации приходят мгновенно: "Студент сдал тест", "Вас добавили в группу".

**Зачем:** Real-time UX. Учитель сидит на странице и видит результаты по мере их поступления.

---

### 29. 📈 A/B тестирование вопросов
**Что:** Учитель создаёт 2 версии одного вопроса → система случайно показывает разным студентам одну из версий → аналитика: какая формулировка понятнее (по проценту правильных ответов).

**Зачем:** Помогает учителю улучшать качество вопросов научным методом.

---

### 30. 🖨️ Печатная версия теста
**Что:** Кнопка "Распечатать" → генерирует PDF с вопросами и вариантами ответов (без правильных), + отдельный PDF с ответами для учителя.

**Зачем:** Не все экзамены проходят онлайн. Иногда нужна бумажная версия (ЕНТ, контрольные).

---

### 31. 🔐 Прокторинг (контроль за студентом через камеру)
**Что:** Во время теста камера записывает видео/делает скриншоты. AI анализирует: студент смотрит в экран? Один ли он? Подозрительные движения?

**Зачем:** Серьёзный анти-чит для дистанционных экзаменов. Университеты готовы за это платить.

**Сложность:** Высокая. Требует согласия студента, хранения видео (дорого), и AI-модели для анализа.
