1. ~~Утечка внутренних ошибок в API-ответах~~ ✅ ЗАКРЫТО
- Все 8 мест в `arena.js` исправлены: `error.message` заменён на безопасный fallback.
- Health endpoint: `error.message` заменён на `'ping_failed'`.
- Добавлен **unified API error handler** в `index.js` — ловит все незахваченные ошибки.
2. ~~Нет защиты CSRF~~ ✅ ЗАКРЫТО
- Реализовано: `middleware/csrf.js` — двойная cookie-стратегия, `ensureCsrfCookie` + `csrfProtection` подключены в `index.js`.

3. ~~Открытый CORS по умолчанию~~ ✅ ЗАКРЫТО
- Реализовано: `ALLOWED_ORIGINS` из `.env`, в production обязателен. Остаётся TODO: переключить `credentials: false → true` для полного robustness.

## Высокий приоритет

4. ~~Слабая генерация `uniqueId`~~ ✅ ЗАКРЫТО
- `arena.js`: `Math.random()` → `crypto.randomBytes(4)` для join codes.
- `arena.js`: Fisher-Yates shuffle с `crypto.randomInt()` для matching.
- `arenaEngine.js`: 50/50 power-up shuffle → `crypto.randomInt()`.
- `User.js`: username suffix → `crypto.randomInt(0, 10000)`.
- `tests.js`: unseeded shuffle → `crypto.randomInt()`.

5. Слишком большой срок жизни JWT
- Проблема: токен на 7 дней без refresh-потока.
- Риск: длительный доступ при краже токена.
- Что делать: сократить TTL access-токена, добавить refresh-токены и ротацию.

6. ~~Нет дополнительных security headers~~ ✅ ЗАКРЫТО
- Реализовано: `helmet()` подключён в `index.js`. `x-powered-by` отключён. CSP пока отключён (нужен для inline-ресурсов).

7. ~~Слабая защита auth-эндпоинтов от брутфорса~~ ✅ ЗАКРЫТО
- Реализовано: `authLimiter` (30/15мин, skipSuccess), `forgotPasswordLimiter` (5/15мин), `resetPasswordLimiter` (10/15мин) в `index.js`.

8. Хранение больших файлов в base64 в MongoDB
- Проблема: медиа переводится в data URL/base64 и хранится в документах.
- Риск: рост размера БД, деградация производительности, дорогие запросы.
- Что делать: вынести медиа в объектное хранилище (S3/аналог), в БД хранить URL + метаданные.

## Средний приоритет

9. ~~Избыточные размеры тела запроса~~ ✅ ЗАКРЫТО
- Глобальный лимит: 50mb → **5mb**.
- `/api/tests`: точечный лимит **25mb** (для base64 медиа в вопросах).

10. Нет единого слоя валидации входных данных
- Проблема: валидация фрагментарная, не для всех полей и эндпоинтов.
- Риск: некорректные данные, потенциальные векторы атак и логические баги.
- Что делать: ввести централизованную схему валидации (например, zod/joi/express-validator).

11. Потенциальный XSS-риск в пользовательском контенте
- Проблема: комментарии и rich text требуют четкой политики очистки/рендера.
- Риск: XSS при изменении фронтенд-рендера в будущем.
- Что делать: серверная/клиентская санитизация + безопасный рендер HTML.

12. ~~Нет механизма сброса пароля~~ ✅ ЗАКРЫТО (частично)
- Реализовано: `/forgot-password` и `/reset-password` маршруты с одноразовыми токенами. Lockout пока не реализован.

## Технический долг по наблюдаемости

13. Недостаточный аудит действий админов
- Проблема: критические действия (бан, смена роли, массовые операции) не всегда журналируются отдельной audit-записью.
- Риск: сложно расследовать инциденты.
- Что делать: добавить audit log (кто/что/когда/откуда).

14. Недостаточная стандартизация обработки ошибок
- Проблема: разные форматы ошибок в разных роутерах.
- Риск: сложно централизованно защищать и мониторить API.
- Что делать: единый error-handler middleware + единый контракт ответа.
