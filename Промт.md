Цель: сгенерировать веб‑UI/GUI для платформы тестирования. Дизайн любой — главное: повторить поведение, валидации и бизнес‑логику проекта в точности.

Обязательные страницы и функции:
- Аутентификация: регистрация, логин, профиль; токен хранится в `localStorage` под ключом `unitest_token` и добавляется в заголовок `Authorization`.
- Каталог тестов: поиск, фильтрация по тегам, сортировка, пагинация; гости видят только публичные тесты.
- Профиль теста: title, description, теги, статистика (кол‑во вопросов, время, участников, рейтинг), типы вопросов; кнопки: старт, practice, копировать ссылку, QR, пожаловаться.
- Редактор теста (create/edit): поля `title`, `description`, `tags`, `questions[]`, `settings`.
	- Поддержать типы вопросов: `single-choice`, `multiple-choice`, `true-false`, `essay`, `matching`, `fill-blank`.
	- Rich text для вопроса, управление опциями (add/remove), отметка корректных ответов, баллы, explanation, загрузка медиа через `/api/tests/upload`.
	- Импорт вопросов из CSV/TSV; экспорт/импорт теста в JSON; автосохранение черновика в `localStorage` (`unitest_draft`) с debounce ≈2s, возможность восстановления/отката.
- Прохождение теста: загрузка по `shareLink`, таймер (в минутах), анти‑чит (tab switch / copy/paste / screenshot), inactivity timeout, варианты/билеты, instant feedback, partial credit.
	- Matching: двухколоночный интерфейс для сопоставления с визуальной подсветкой пар.
	- Клавиатурные шорткаты: 1–9 для опций, Enter — следующий/сабмит, стрелки — навигация.
- Результаты: сабмит результата, просмотр результатов, ручная оценка эссе (только создатель), лидерборд, аналитика вопросов.

Краткая спецификация API (обязательна для реализации запросов):
- POST /api/auth/register → { token, user }
- POST /api/auth/login → { token, user }
- GET /api/tests?search,tag,sort,page,limit → список тестов
- POST /api/tests (auth) — создать тест
- PUT /api/tests/:id (auth, creator) — обновить тест
- GET /api/tests/:id (auth) — получить тест для редактирования
- GET /api/tests/share/:shareLink (optionalAuth) — получить тест для прохождения
- POST /api/tests/upload — multipart file → { url, type, fileName }
- POST /api/tests/:id/check-answer — { questionId, selectedOptions, textAnswer, matchingPairs } → { isCorrect, correctOptionIds, correctText, correctPairs, explanation, partialPoints }
- POST /api/results — отправка результата: { testId, answers, guestName?, guestId?, violations?, timeSpent?, variantNumber? }
- GET /api/results/test/:testId (auth, creator) — результаты
- PUT /api/results/:resultId/grade-essay (auth, creator) — ручная оценка эссе

Ключевые структуры данных (следовать формату):
- Test: { title, description, creator, questions: [Question], settings, shareLink, tags }
- Question: { id, type, questionText, passage, points, options: [Option], correctAnswer, media: {type,url,fileName}, explanation }
- Option: { id, text, isCorrect, matchPair }
- Result: { test, user?, guestName?, guestId?, answers: [{ questionId, selectedOptions, textAnswer, matchingPairs }], score, totalPoints }

Критичные валидации и правила подсчёта (точно как в проекте):
- `title` обязателен; у каждого вопроса должен быть текст.
- Для `single-choice`, `true-false`, `multiple-choice` — хотя бы одна правильная опция.
- Для `fill-blank` — корректный текст ответа.
- Partial credit (если включён в settings):
	- `multiple-choice`: partial = max(0, (correct_selected − wrong_selected) / total_correct) * points
	- `matching`: partial = correctly_matched / total_pairs * points
- Сервер не должен отдавать правильные ответы при выдаче теста для прохождения.

UX-заметки (свободно): адаптивный интерфейс, индикация автосохранения и состояния сети, подтверждения удаления/сабмита, понятные ошибки валидации.
